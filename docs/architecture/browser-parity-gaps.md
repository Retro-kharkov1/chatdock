# Browser parity gaps (Chrome vs. the app)

<overview>
Analysis dated 2026-10-09 (Electron 44.4.3 per `package.json`). Question from the maintainer: what can Chrome do
for Google Chat (and the linked Meet / Drive / Docs windows) that this shell cannot yet? Evidence is the code
(paths relative to `C:\Repos\Retro-kharkov1\google-chat-desktop`) and Electron's documentation. **Nothing here was
run**: items marked "unverified" need a check in a real desktop session before a fix is scoped (see the
*Verify on a real desktop* rule in [Project Rules](project-rules.md)).

**File drag-and-drop into the page** and **file attach (file chooser)** (BUG-07, BUG-08) are fixed: see
[File access](file-access.md). Two causes: the denied `fileSystem` permission (drop) and a picker that Chromium cancels (attach); the fix covers the
main window, the Google app windows and the Meet call window.

Root cause to keep in mind for most rows below: Electron ships **no browser chrome**. Everything Chrome gives
around the page (context menu, zoom, find, reload, back/forward, print, download bubble, password manager) is
either absent or must be written by the app. This app additionally removes the application menu
(`src/main/index.js:129`, `Menu.setApplicationMenu(null)`, needed so there is no second Quit path), which also removes
the menu accelerators Electron would otherwise provide for free.
</overview>

<legend>
Status: **works** / **broken** / **missing** (Chrome has it, the app has nothing) / **excluded** (deliberately blocked
by a project rule) / **unverified** (code reading cannot settle it). Severity is for daily use of Chat.
</legend>

## Ranked top list (daily-use impact)

1. **File drop and file attach** — known, being fixed; repeat in Drive/Docs windows after.
2. **No context menu** (row 1) — no Cut/Copy/Paste menu, no spelling fix, no Copy/Save image anywhere the page does not draw its own menu.
3. **No Reload / failed-load recovery** (row 3) — a failed launch needs quit and relaunch.
4. **Spellcheck without suggestions or language choice** (rows 1-2) — the biggest effect for users who write in more than one language.
5. **No keyboard zoom** (row 4) — accessibility and HiDPI.
6. **Paste of screenshots/files unverified** (row 5) — verify first, it is the most common Chat action after typing.
7. **Fullscreen in Meet and Chat, clipboard write in Meet/Gmail/Calendar** (rows 8-9) — permission lists are too narrow; needs evidence from a real call plus a maintainer decision.
8. **Downloads give no progress or completion feedback** (row 7) — rule-bound; needs a decision.
9. **Drag out of the page unverified** (row 15).
10. Back/forward, find, print, corporate proxy/SSO auth (rows 12-14, 19) — lower, request-driven.

## Suggested grouping for implementation

- **Pass A (no rule change, one coherent change):** rows 1, 2, 3, 4, 6 — a native context menu, reload, zoom and editing shortcuts, all in the main process, no preload change, no new window. Extends `editShortcuts.js` and adds one module next to `smartCopy.js`; must be bound to the main window and the Google app windows, not the call window (call window keeps its minimal surface).
- **Pass B (needs maintainer decision, list changes in `session.js`):** rows 7, 8, 9, 10.
- **Verification first (no code):** rows 5, 14, 15, 20, 27 and Ctrl+wheel zoom in row 4.
